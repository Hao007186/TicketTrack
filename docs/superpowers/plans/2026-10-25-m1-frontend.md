# M1 前端 Implementation Plan

> **For agentic workers:** REQUIRED SUB-SKILL: Use superpowers:subagent-driven-development (recommended) or superpowers:executing-plans to implement this plan task-by-task. Steps use checkbox (`- [ ]`) syntax for tracking.

**Goal：** 做出 FareWatch 的網站前端，接上 #2～#5 的 API；後端補上詳情頁需要的兩個欄位與 OpenAPI 輸出。

**Architecture：** `frontend/` 是 Vite + React + TypeScript 的單頁應用。所有 API 呼叫都經過 `api/client.ts` 的 `authFetch`：帶 token，401 時透過 `auth/token.ts` 排隊 refresh 後重送。資料用 TanStack Query 管理，頁面放在 `pages/`，共用元件放在 `components/`。API 型別從後端的 `openapi.json` 產生。

**Tech Stack：** React 19、TypeScript、Vite、React Router（`react-router` 套件）、TanStack Query v5、Recharts、Tailwind v4（`@tailwindcss/vite`）、openapi-typescript + openapi-fetch、Vitest + Testing Library + MSW 2、eslint（typescript-eslint、react-hooks）、prettier。版本用安裝當下的最新穩定版，由 `package-lock.json` 鎖定。

**Spec：** [docs/superpowers/specs/2026-10-25-m1-frontend-design.md](../specs/2026-10-25-m1-frontend-design.md)

## Global Constraints
- Node.js 22 LTS；套件管理用 npm，`package-lock.json` 要 commit
- 介面文字一律繁體中文；金額 `NT$ 10,372`（`Intl.NumberFormat("zh-TW")`）；時間一律 `Asia/Taipei`
- access token 只放在模組變數，**不得**寫進 localStorage、sessionStorage 或 cookie
- 跨分頁 refresh 的鎖名稱：`farewatch-refresh`
- API 一律走 `/api/v1/...` 相對路徑；開發時由 Vite proxy 轉給 `http://localhost:8000`；後端不加 CORS
- openapi-fetch 的 `baseUrl` 用 `window.location.origin`（測試環境的 `Request` 不接受相對網址）
- 名額只算 `active`、`queued`，上限 3（`MAX_WATCHES = 3`）；出發日在今天（台灣時間）起 3～330 天內（`MIN_DAYS_AHEAD = 3`、`MAX_DAYS_AHEAD = 330`），和後端相同
- 示範帳號的寫入按鈕一律用 `WriteButton`；403 仍由全域 mutation 錯誤處理顯示「示範帳號無法修改」
- `.prettierrc` 設 `"endOfLine": "auto"`（本機 Windows 的 git 會轉成 CRLF，CI 是 LF）
- 前端測試不連後端，API 一律用 MSW 假造；`navigator.locks` 在 jsdom 不存在，需要時在測試裡自己裝一個假的
- 後端：指令在 `backend/` 下執行；全套驗證是 `uv run pytest -q && uv run ruff check && uv run ruff format --check && uv run mypy`
- 前端：指令在 `frontend/` 下執行；全套驗證是 `npm run lint && npm run typecheck && npm test && npm run build`
- Commit 用 Conventional Commits、繁體中文，結尾 `Co-Authored-By: Claude Opus 5.5 <noreply@anthropic.com>`；寫檔用編輯工具，不用 bash heredoc

## Review Focus
1. **兩個分頁同時重新整理**：只有一個分頁送出舊的 refresh token，另一個等鎖釋放後送新的，兩個都保持登入 → Task 3 測試（假的 `navigator.locks` 讓兩個呼叫依序執行，第二個用的是第一個換到之後的狀態）
2. **refresh 進行中又有新的請求遇到 401**：共用同一個 refresh，不會送出第二個 → Task 3 測試
3. **登入頁的 `next` 是 `//evil.com` 或 `https://evil.com`**：忽略，導到 `/watches` → Task 4 測試
4. **編輯時把來回改成單程**：送出的 body 含 `return_date: null`；沒有動到的欄位不送 → Task 6 測試
5. **通知連到的追蹤已被刪除**：詳情頁顯示「找不到這個追蹤，可能已被刪除」，不是空白頁或無限載入 → Task 7 測試

**Interfaces:**
- Produces:
  - `auth/token.ts`：
    - `getAccessToken(): string | null`、`setAccessToken(token: string | null): void`
    - `refreshAccessToken(): Promise<string | null>`：同一個分頁有 refresh 進行中時回傳同一個 promise；有 `navigator.locks` 時在 `navigator.locks.request("farewatch-refresh", ...)` 裡面送 `POST /api/v1/auth/refresh`（`credentials: "same-origin"`，用全域 `fetch`，不經過 `authFetch`）；200 → 存下新 token 並回傳；401 → `setAccessToken(null)` 並回傳 `null`；網路錯誤 → 往外丟
    - `onAuthLost(handler: () => void): () => void`：註冊「refresh 失敗、登入已失效」時要呼叫的函式，回傳取消註冊的函式
  - `api/errors.ts`：
    - `class ApiError extends Error { readonly status: number }`，`message` 就是給使用者看的中文
    - `toApiError(status: number, body: unknown): ApiError`：`detail` 是字串 → 直接用；是陣列 → 取每項的 `msg`，用「；」串起來；都沒有 → 依 status：403「示範帳號無法修改」、404「找不到資料」、其他「連線失敗，請稍後再試」
    - `errorMessage(e: unknown): string`：`ApiError` → `message`；其他 → 「連線失敗，請稍後再試」
  - `api/client.ts`：
    - `authFetch(request: Request): Promise<Response>`：帶上 `Authorization: Bearer <token>`（有 token 時）；回 401 而且路徑不是 `/api/v1/auth/` 開頭 → `refreshAccessToken()`，拿到新 token 就用**送出前先 clone 的 request** 重送一次；拿到 `null` 就呼叫 `onAuthLost` 的 handler，回傳原本的 401
    - `api = createClient<paths>({ baseUrl: window.location.origin, fetch: authFetch })`
    - `unwrap<T>(result: { data?: T; error?: unknown; response: Response }): T`：有 `error` 或 `!response.ok` 就丟 `toApiError(response.status, error)`；204 回 `undefined as T`

- `refresh 成功時存下 token`：回 `{ access_token: "new", token_type: "bearer" }` → 回傳 `"new"`、`getAccessToken() === "new"`

- `同時呼叫只送一次`：`Promise.all` 呼叫 3 次 → handler 被呼叫 1 次，3 個結果都是同一個 token
- `跨分頁用 navigator.locks 排隊`：裝一個假的 `navigator.locks`，`request(name, cb)` 把呼叫串成佇列並記下 `name`；在 handler 裡用一個計數器回 `"t1"`、`"t2"`。先 `await` 第一次，再呼叫第二次（模擬另一個分頁拿到鎖）→ 兩次都成功，`name === "farewatch-refresh"`，而且 handler 是在第一次的鎖釋放後才被呼叫第二次

`client.test.ts`：
- `帶上 token`：`setAccessToken("abc")` → handler 收到 `Authorization: Bearer abc`
- `401 後 refresh 並重送`：`/api/v1/me` 第一次 401、refresh 回 `"new"`、第二次收到 `Bearer new` 才回 200 → `unwrap` 得到資料
- `兩個請求同時 401 只 refresh 一次`：refresh handler 計數 1
- `refresh 失敗時呼叫 onAuthLost`：refresh 401 → handler 被呼叫 1 次，`unwrap` 丟出 status 401 的 `ApiError`
- `重送後仍 401 不再重試`：`/api/v1/me` 永遠 401、refresh 永遠成功 → `/me` 被呼叫 2 次、refresh 1 次
- `auth 端點的 401 不觸發 refresh`：`POST /api/v1/auth/login` 回 401 → refresh 次數 0
- `POST 重送時帶著原本的 body`：`POST /api/v1/watches` 第一次 401，第二次 handler 讀到的 JSON 和送出的一樣
